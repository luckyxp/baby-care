# 宝宝护理 · 三方协同 H5

育儿嫂 × 爸爸 × 妈妈 的宝宝护理协同应用。育儿嫂不用手写早教和喂养方案，三方信息实时互通，每天自动生成交接汇报，替代杂乱的微信群沟通和容易出错的口头交接。

> 当前阶段为**纯静态托管**：没有服务器，"云端"由浏览器内的模拟云（同源 IndexedDB）扮演，接口形状与未来真实后端一致，替换传输层即可上线。

## 功能一览

| 模块 | 能力 |
|---|---|
| 角色权限 | 育儿嫂创建宝宝档案即成为管理员；生成 6 位邀请码（7 天有效、一次性）邀请爸爸妈妈；家长可查看、补充备注、完成晚间亲子任务，不能修改计划与育儿嫂录入的内容，不能管理成员 |
| 护理日志 | 奶量（配方/母乳瓶喂/亲喂）、辅食、排便、睡眠（进行中计时）、体温、用药、成长、其他；每条标注填写人；语音一句话录入多条；异常自动标红；离线可记，联网自动同步 |
| 消息推送 | 他人新增记录、宝宝睡醒、补充备注、任务打卡、汇报发布 → 消息中心 + 前台横幅 + 后台系统通知 |
| 计划 | 按生日自动匹配 11 个月龄阶段方案；每日自动生成喂养作息 + 五大领域早教 + 日间亲子 + 晚间（留给父母）亲子；育儿嫂可换一个/换一批/从素材库挑选/自定义；打卡记录宝宝表现；喂奶按日志自动完成 |
| 素材库 | 110 条早教（大运动/精细动作/感官认知/语言启蒙/亲子社交）、31 条亲子互动、64 种食材、40 道辅食食谱、喂养原则 |
| 每日汇报 | 自动抓取喂养、睡眠、排便、健康、早教打卡、亲子、家人留言生成分块汇报；育儿嫂可逐块改写（刷新数据不覆盖改写）、一键复制到微信、发布给家长；历史汇报可回看 |
| 数据看板 | 日/周/月统计：奶量、睡眠、排便、体温；五大早教领域完成频次与雷达图；日间/晚间亲子完成率 |
| 隐私与体验 | 数据只下发给本家庭成员；被移出后立即失去访问且本地副本被清除；快捷记录一点即存、沿用上次习惯值；PWA 可添加到主屏幕、断网可打开；暗色模式 |

## 快速开始

```bash
npm install
npm run dev        # 开发：http://localhost:5173（--host 已开启，手机同局域网可访问）
npm test           # 单元测试（vitest）
npm run build      # 类型检查 + 构建到 dist/
npm run preview    # 本地预览构建产物
```

### 体验三方实时同步

1. 打开登录页，点击「一键体验」中的 **育儿嫂**（会在本地生成三个演示账号与一周数据）。
2. **另开一个浏览器标签页**，同样打开应用，选择 **妈妈** 或 **爸爸**。
3. 在育儿嫂标签页记录一次喂奶 → 家长标签页立即出现记录和消息提醒。
4. 在「我的」中打开 **模拟离线**，记录几条后关闭 → 待上传记录自动补传。

> 不同标签页可以登录不同账号（会话优先保存在 sessionStorage）。

## 部署（静态托管）

`npm run build` 后将 `dist/` 上传到任意静态托管即可（Nginx、OSS/COS、GitHub Pages、Vercel、Netlify…）：

- 产物使用相对路径（`base: './'`）+ Hash 路由，可部署在任意子目录，**无需**服务端回退配置；
- Service Worker 与语音识别、剪贴板等能力需要 **HTTPS**（localhost 除外）；
- 纯静态阶段，所有数据保存在各自设备的浏览器中，**跨设备同步需要接入后端**（见下文）。

## 目录结构

```
src/
├── shared/        领域契约：types（实体/同步协议）、constants（中文标签）、policy（权限表）、errors
├── cloud/         模拟云端：db（云数据库）、server（账号/家庭/邀请/权限裁决/增量同步）、notify（消息分发）、demo（演示数据）
├── sync/          transport（传输层接口）、engine（离线队列 + 推拉同步）、network（网络状态/模拟离线）
├── db/            client（每账号一个本地副本）、repo（写入：权限预检 + 乐观落库 + 入队）、live（响应式查询）
├── domain/        纯业务逻辑：log-kinds、voice-parser、planner、stats、report、dashboard
├── library/       内置素材库：月龄阶段、早教、亲子互动、食材与食谱
├── services/      页面调用的业务操作：logs、plan、report
├── stores/        session（登录态/身份/当前宝宝）、ui（主题/提醒）
├── composables/   useDay、useClock、useAction、useVoice、useNotices、alerts
├── components/    公共组件（LogSheet、VoiceSheet、NoteThread、ChipGroup…）与 plan/report/charts/family 子目录
└── views/         页面
tests/             vitest：云端权限/同步、计划、汇报、素材库、语音解析、演示数据
docs/DESIGN.md     架构与数据同步设计
```

## 接入真实后端

前端只通过 `src/sync/transport.ts` 的 `Transport` 接口与"云"交互。上线时：

1. 按 `docs/DESIGN.md` 的接口约定实现后端（服务端逻辑可直接参照 `src/cloud/server.ts`，权限规则复用 `src/shared/policy.ts`）；
2. 实现 `HttpTransport`（fetch + WebSocket/SSE 推送 `{familyId, seq}`），替换 `transport.ts` 底部导出；
3. 删除 `src/cloud/`（模拟云）与登录页的一键体验入口。

业务页面、同步引擎、本地库均无需改动。
